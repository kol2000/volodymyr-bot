# Прогнозирование: общий цикл (27 ноября 2026)

## Что завершено
`forecast_service.py` используется из `Predictions.answer` и `forecast_cycle.py`:
- европейские национальные чемпионаты из календаря (основные пять + поддерживаемые ФНК лиги), РПЛ и Кубок России;
- взрослые сборные: ЧМ/Евро, квалификация, Лига наций, товарищеские;
- Лига чемпионов и Лига Европы;
- расчёт клубов по прошлым результатам, экспериментальный Elo сборных при наличии локальной истории; резервная LLM-оценка; явно помеченный нейтральный сценарий при недоступности обоих источников;
- единый рынок: исход за 90 минут + добавленное, не проход и не серия пенальти;
- неизменяемый журнал прогнозов до начала, SHA-256, отдельные результаты, отчёт по турнирам;
- Кубок России: для прогнозов включён и путь регионов, политика живых уведомлений сохранена;
- французский V8 register_v2 получил `--write`, сохраняя оригинальные наблюдения и проверку источника.

Это завершение функционального цикла, а не доказательство прибыльности/точности модели. `production_eligible=False` сохраняется как признак отсутствия валидации качества. Старые исследовательские наблюдения V8 не переписываются. Экспериментальный V8 cache при `BUBUS_FORECAST_V8_MODE=on` остаётся приоритетным там, где уже был настроен; остальные запросы переходят в общий модуль.

## Запуск
Из корня проекта на Ubuntu/Python 3.12:
```bash
python3 -B forecast_cycle.py --days 2 --limit 2
python3 -B forecast_cycle.py --days 3 --limit 20 --with-model --write
python3 -B forecast_cycle.py --report
python3 -B football_forecast_v8_ligue1_register_v2.py
python3 -B football_forecast_v8_ligue1_register_v2.py --write
```
По умолчанию цикл без записи и без LLM. `--with-model` использует существующий `state/config.json` через common.load_config, не создаёт Bot/Telegram client. `--limit` ограничивает новые расчёты за запуск; остаток переносится на следующие запуски. Ошибка одного календаря/матча не останавливает другие турниры.

Новая установка: выполнить обычный setup.py из README для конфигурации; установить ffmpeg/Tesseract, если нужны видео. История сборных необязательна для резервного прогноза: `state/football_expansion/international_results.sqlite3`; импорт/исследование описаны в `football_expansion_v9.py --help` и `football_nations_v10.py --help`. История и снимки старых V8 хранятся только на ВМ; клонирование GitHub само по себе их не восстанавливает. Отсутствие архива не разрешает генерировать задним числом исторические наблюдения.

Для включения почасового цикла на существующей ВМ:
```bash
sudo bash /home/botadmin/volodymyr_bot/install_forecast_cycle.sh
```
Скрипт устанавливает отдельные `bubus-forecast-cycle.service/.timer` и перезапускает основного бота. Старые таймеры V8 сохраняет. Модель и сеть могут занимать время; запуск ограничен 45 минутами, `flock` исключает наложение запусков цикла. Ничего не публикуется в Telegram автоматически.

## Данные и ограничения
Журнал: `state/football_forecasts/{observations,results}`. Первое наблюдение данного ID/турнира сохраняется; новые расчёты не заменяют исторический прогноз. У пользовательского ответа может быть более свежий расчёт. Разные source ID объединяются по турниру, нормализованным командам и времени начала. При расхождении времени требуется отдельная проверка переноса.
Результат фиксируется после финального статуса и минимум двух часов от старта. Для кубков/сборных требуется полная последовательность голов, чтобы отделить дополнительное время. Неоднозначный 0:0 и неполная лента остаются `regulation_unconfirmed`; перенос начала — `schedule_changed`. Не превращать такие случаи в выдуманный результат. Исправление уже сохранённого результата выдаёт `result_conflict`, а не перезаписывает его.
Проценты показываются только для статистического расчёта. Счёт от LLM не превращается в придуманные вероятности. Нейтральность поля сборных не всегда известна: базовый Elo использует нейтральное поле и явно сообщает об этом. Травмы/составы/ротация и сила разных лиг не проверяются автоматически.
