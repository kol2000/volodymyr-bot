# Telegram-бот-пародия с локальной моделью

Требуются Ubuntu 24.04, Python 3.12 и локально установленная модель
`qwen3:30b-a3b-instruct-2507-q4_K_M` в Ollama.
Должен быть обеспечен доступ к Telegram. Используется исходящий long polling;
проброс портов для бота не требуется. Нужен Python 3.12 с SQLite FTS5, поставляемый Ubuntu;
зависимостей pip нет.
Для курсов и погоды нужны исходящие HTTPS-запросы к ЦБ, CoinGecko и Open-Meteo.
Платные ключи и дополнительные настройки не требуются.

## Установка

1. Создайте НОВОГО бота через официальный @BotFather, команда `/newbot`.
   Назовите его явно: например, «Володимир AI — пародия». Username заканчивается на `bot`.
   В описание через `/setdescription` добавьте, что это бот-пародия, а не реальный участник.
2. Через `/setprivacy` выберите нового бота и `Disable`.
   Сделайте это до добавления бота в группу: ему нужен контекст обычных сообщений.
   Права администратора для этой реализации не требуются; разрешите боту отправлять сообщения.
3. Скачайте ZIP и перенесите через MobaXterm в `/home/botadmin/`.
4. В SSH-сеансе botadmin выполните:

```bash
cd /home/botadmin
unzip volodymyr_bot_install.zip
cd volodymyr_bot
python3 setup.py
```

Токен вводится скрыто в терминале VM. Не отправляйте его в ChatGPT, скриншоты или группу.
Настройка проверит Telegram и установленную модель, затем предложит отправить новому боту
`/start` в личных сообщениях. Выберите свой аккаунт владельца из найденных сообщений.
Токен останется в `state/config.json` с правами 600. Настройка не перезаписывает существующий конфиг.

```bash
bash install_service.sh
```

Это установит службу `volodymyr-bot`, включит запуск при загрузке Ubuntu и перезапуск
после сбоя процесса. Сетевые ошибки и отключения VPN обрабатываются повторным подключением.
Автозапуск самого VPN должен быть настроен отдельно в вашем VPN-клиенте.

## Первый тест

Добавьте бота в нужную группу и со своего аккаунта отправьте:

```text
/bubus
```

Первый `/bubus` от владельца подключает группу и выдаёт случайную короткую фразу
из архива без обращения к модели. Если владелец вызывает команду в другой группе,
бот переключается на неё и выключает автоматические реплики. В текущей группе
повторный вызов сохраняет установленный автоматический режим.

Все участники подключённой группы могут вызывать `/bubus` для случайной фразы.
С текстом, например `/bubus где пивас`, команда выдаёт ответ модели по теме.
Можно также ответить на сообщение бота обычным текстом или упомянуть его username.
Старая `/bind` удалена из обработки и меню; отдельная команда подключения не нужна.
Административные команды доступны только владельцу.

Автоматический режим включается отдельно командой владельца `/auto_on`.
Сам по себе `/bubus` его не включает. Другие группы обслуживаются только после
вызова владельцем `/bubus` в них. Владелец может тестировать бота и в личных сообщениях.

## Реакции на ключевые слова и характер

Бот реагирует на отдельные слова без учёта регистра:
`бубуська`, `володька`, `рахиня`, `украина`, `война`, `киев`, `цаца`, `цацик`, `бубус`,
`цацыг`, `хряк`, `свинья`, `сосатка`, `крым`, `крим`, `даг`.
Также распознаётся фраза `крым наш`, включая несколько пробелов между словами.
Фраза учитывается как один триггер; несколько совпадений в сообщении дают один ответ.
Это прямые обращения: они работают и при выключенном `/auto_on`, в том числе ночью.
Несколько ключевых слов в одном сообщении создают один ответ; случайные совпадения
внутри других слов не срабатывают. Команды, адресованные другим ботам, игнорируются.
Для прямых обращений действует пауза 15 секунд; дневного лимита нет.
При паузе или заполненной очереди обращение в группе молча
пропускается: техническое уведомление о занятости остаётся только в личном чате владельца.
Команда `/status` показывает очередь, обработку текущего задания, оставшуюся паузу,
время последнего полученного обращения в группе и причину последнего пропуска.

Модель отвечает в манере злого, раздражительного и язвительного участника:
резкие возражения, раздражённые вопросы и подколы по теме, мат по ситуации.
Написание сверено с архивом: обязательны `ти`, `ето`, `ещо`, `било`, `би`, `сечас`
и глагольные окончания `-еш/-иш`: `пишеш`, `знаеш`, `будеш`, `говориш`.
Эти написания закреплены в инструкции и исправляются перед отправкой, включая
ответы модели, случайные архивные фразы и резервные реплики. В словах `опять`,
`хоть`, `делать`, `есть` мягкий знак сохраняется, как в исходной истории.
`Что/шо`, `только/токо`, `сколько/скоко` остаются вариантами по смыслу.
Проверка повторов учитывает эти замены и не считает новую орфографию новой репликой.
К политическим словам применяется резкая реакция на реплику собеседника;
угрозы и ненависть к народам или жителям города запрещены инструкцией.
Обычная `/bubus` без текста выбирает случайную исходную фразу из архива;
теперь отбираются короткие резкие реплики с руганью. Модель при этом не вызывается.

## Курсы и погода

Обычное сообщение с суммой вызывает пересчёт без команды: `100 USDT`, `50 USD`,
`$50`, `5000 рублей`, `0,25 BTC`. Поддерживаются USD, RUB, USDT, USDC, BTC, ETH,
BNB, SOL, TON и DOGE. В одном ответе обрабатываются до трёх разных сумм.
Запятые и точки подходят для десятичной части; пробелы — для тысяч.
Суммы внутри ссылок, адресов кошельков и username игнорируются.

- USD → RUB и RUB → USD: официальный курс [ЦБ](https://www.cbr.ru/development/sxml/)
  на текущую московскую дату. В выходные показывается дата последнего действующего курса.
- Криптовалюта → USD: цена [CoinGecko](https://docs.coingecko.com/docs/keyless-public-api).
  USDT и USDC не приравниваются автоматически к доллару: используется их текущая цена.
- Рублёвый эквивалент криптовалюты считается через USD и курс ЦБ. Это оценка,
  которая может отличаться от курса обменника или P2P. В ответе указаны дата ЦБ
  и время обновления криптовалютной цены.

Погода: `Володька, какая погода в городе Орёл`, `погода в Орле` или `/weather Орёл`.
Бот показывает текущую температуру, ощущаемую температуру, состояние погоды,
ветер в м/с, влажность и осадки за последний интервал. Подпись содержит место,
дату и местное время данных [Open-Meteo](https://open-meteo.com/en/docs).
Это модельная оценка текущей погоды, не гарантированное измерение на месте.
Сейчас реализована текущая погода; прогноз на завтра или неделю не подменяется ею.
Если город неоднозначен, бот просит уточнение, например `/weather Орёл, Россия`.

Справочные ответы не генерируются языковой моделью и имеют отдельный поток и очередь,
поэтому работают и во время её загрузки или занятости. Цифры не придумываются.
Курсы и погода имеют приоритет над пародийной реакцией: одно сообщение даёт один ответ.
Внешним сервисам передаются только название города либо идентификаторы валют;
полное сообщение, история чата и архив им не отправляются.
Кэш: курс ЦБ — час с обновлением на новой московской дате; криптовалюта — минуту;
погода — пять минут. Криптоцены старше 15 минут и погодные данные старше 90 минут
отбрасываются. При недоступном сервисе бот коротко сообщает, что свежие данные
не получены, и пишет фиксированную причину в журнал.

Общие правила доступа к группе, игнорирования ботов и старых обновлений сохраняются.
Между обращениями остаётся пауза 15 секунд. Если ответ готов во время паузы после
другой отправки, справочный поток ожидает её окончания; устаревшее задание отменяется.
Справочные запросы доступны участникам подключённой группы; в личном чате — владельцу.

## Если модель не сформировала ответ

При повторе, пустом или неподходящем ответе выполняется ещё одна генерация:
без архивных примеров, с сокращённым контекстом и указанием причины отклонения.
Тайм-аут обращения к Ollama ограничен 90 секундами. После тайм-аута ещё один запрос
сразу не запускается: предыдущая генерация могла остаться в работе.

Если получить реплику не удалось, на прямое обращение выбирается короткая резервная
фраза в характере бота: из тематического набора или 36 общих реплик. Эти фразы написаны
локально, не содержат сведений из частного архива и не требуют работающей модели.
Последние 30 ответов исключаются из выбора. Техническая фраза «Не получилось
ответить. Попробуй позже.» больше не отправляется.

Резервные ответы проходят обычные ограничения группы, паузы и суточных лимитов,
записываются в историю. При сбое автоматической генерации бот молчит. Неопределённая
отправка в Telegram не повторяется. Сообщение, состоящее только из вызова другого
бота (например, `@other_bot`), не вызывает ответ Бубуса даже в reply к его реплике.
Причины отклонения и факт выбора резервной фразы видны только в журнале службы.

Проверка повторов учитывает изменения вступления, разговорного написания и общего
фрагмента реплики. Недавние ответы бота хранятся для локальной проверки, но не
передаются модели: список прежних фраз мог подталкивать её к их воспроизведению.
На сообщение только из ключевых слов модель получает свежий вызов без архивных
примеров и старого контекста. На полноценные сообщения поиск примеров сохраняется.
Упоминания киборга допускаются только когда это есть в текущем обращении; присказка
про забытого Бубуса отбрасывается, если пользователь не спрашивал о забывании.

## Приветствие при вступлении

Когда Telegram сообщает о вступлении или повторном вступлении пользователя
с точным username `@leonadosasa` в подключённую группу, бот отвечает на сообщение
о входе фразой: `оо алкаш епти ти де бил?`.
Username сопоставляется без учёта регистра; display name и username пригласившего
человека не используются. Настроено написание из последнего запроса пользователя,
без добавления похожих username.

Приветствие отправляется без модели, независимо от `/auto_on` и тихих часов.
Оно не расходует лимит 5 автоматических попыток в сутки. Как и любая
реплика бота, оно отодвигает обычное автоматическое вмешательство минимум на час.
Каждое событие обрабатывается один раз, в том числе после перезапуска. При неясном
результате отправки приветствие вслепую не повторяется. Старые события старше
двух минут после сетевого простоя пропускаются.

Срабатывает событие вступления в группу, а не открытие чата или появление онлайн.
Telegram должен передать боту служебное сообщение `new_chat_members`.
Установка обновления не создаёт приветствие для уже находящегося в группе участника.

## Режимы и лимиты

- `/bubus` без текста: случайная короткая фраза из архива без модели.
- По теме: `/bubus текст`, @упоминание или ответ на реплику бота.
- Автоматически: случайная проверка беседы каждые 1–3 часа и вероятность 3% реагирования
  на обычное входящее сообщение, когда остальные ограничения разрешают отправку.
- Не более 5 попыток автоматической отправки в сутки, по московскому времени.
- Минимум 60 минут после последней реплики бота перед автоматическим вмешательством.
- Тихие часы для автоматического режима: 00:00–10:00 Europe/Moscow.
- Автоматические ответы только если участники писали в последние 2 часа. Модель может
  выбрать молчание. Расписание не гарантирует пять сообщений каждый день.
- Ответы по обращению: не чаще раза в 15 секунд, без дневного лимита.
  Тихие часы не запрещают прямое обращение.
- Один поток генерации, очередь максимум 4 задания. Устаревшие задания отбрасываются.
- Настройки, лимиты и положение в очереди Telegram сохраняются в SQLite. Внутренняя очередь
  генерации находится в памяти; при рестарте незавершённое задание может быть пропущено.
- После неясного результата sendMessage сообщение не отправляется повторно вслепую,
  чтобы не получить дубликат. Такие попытки консервативно учитываются в лимите.

## Команды владельца

| Команда | Действие |
|---|---|
| `/bubus` | Случайная фраза; первый вызов владельцем подключает группу |
| `/bubus текст` | Получить ответ модели по теме |
| `/weather Орёл` | Погода сейчас в указанном городе |
| `/convert 100 USDT` | Пересчитать сумму в USD/RUB |
| `/auto_on` | Включить автоматические реплики для подключённой группы |
| `/auto_off` | Выключить автоматические реплики, сохранить ответы по обращению |
| `/status` | Показать группу, состояние, очередь и сегодняшние лимиты |
| `/whoami` в личных сообщениях | Показать Telegram ID |

## Контекст и стиль

В пакет включено 22 352 коротких примера из предоставленного архива. Часть примеров содержит
реплику собеседника, чтобы искать не только похожие слова, но и похожие ситуации.
SQLite FTS5 выбирает подходящие примеры локально; модель получает несколько примеров,
последние сообщения и описание стиля. Это подбор примеров в запросе, а не дообучение весов.

История в рабочей базе ограничена 200 текстами на чат; в запрос идут до 6 недавних
сообщений людей. Последние 30 ответов бота проверяются локально и в запрос не включаются.
Ссылки, похожие на телефонные номера строки и email заменяются маркерами. Это ограниченная
автоматическая обработка, а не полная анонимизация. Архив и рабочая история остаются на VM
и не отправляются внешней модели. Telegram получает готовые сообщения бота.

Длинные или оборванные ответы, явные рассуждения о задании и некоторые групповые оскорбления
отбрасываются. Фильтр не гарантирует идеальное качество или полную защиту от нежелательного текста.
Первое включение предусмотрено в тестовой группе. При неточном стиле пришлите несколько
примеров ответов без токена; описание и поиск можно настроить.

## Обновление через GitHub

В Git хранятся код, инструкция модели и скрипты. `state/` и `data/examples.jsonl`
исключены из Git: токен, рабочая история и архив переписки сохраняются только на VM.
При новом развёртывании корпус нужно перенести из существующей установки или пакета.

Репозиторий `kol2000/volodymyr-bot` публичный. Для скачивания и обновления по HTTPS
вход в GitHub и SSH-ключ не нужны. Выполните однократный переход из старой установки
в SSH-сеансе пользователя `botadmin`:

```bash
sudo apt install -y git
git clone https://github.com/kol2000/volodymyr-bot.git /home/botadmin/volodymyr_bot_checkout
bash /home/botadmin/volodymyr_bot_checkout/migrate_to_git.sh
```

Скрипт сначала проверяет код, затем останавливает службу, переносит состояние и корпус,
сохраняет прежнюю установку и запускает службу. При ошибке переноса он восстанавливает
прежний каталог. Повторно запускать setup.py не требуется.

Все последующие обновления:

```bash
bash /home/botadmin/volodymyr_bot/update.sh
```

Обновление использует `git pull --ff-only`, запускает проверки и перезапускает службу
после их успеха. Если есть локальные изменения кода или проверки не прошли,
скрипт остановится без перезапуска службы. Ключевые слова работают после рестарта.

## Обновление установленного бота архивом

Скопируйте свежий `volodymyr_bot_install.zip` в `/home/botadmin/` и выполните:

```bash
sudo systemctl stop volodymyr-bot
unzip -o /home/botadmin/volodymyr_bot_install.zip -d /home/botadmin
sudo systemctl start volodymyr-bot
sudo systemctl status volodymyr-bot --no-pager
```

В ZIP нет каталога `state`: токен, привязка группы, история и лимиты сохраняются.
Повторно запускать `setup.py` или подключать текущую группу не требуется.
Команды `/say` и `/bind` больше не обслуживаются. Используйте `/bubus` для случайной фразы, `/bubus текст`,
`/bubus@volodymyr_bubus_bot текст` для этого бота или обычный текст в ответ на его сообщение.
Постоянные фразы больше не добавляются к каждому запросу. Если модель повторила
один из последних 30 ответов или его близкий вариант, выдала пустой, оборванный, слишком длинный или другой
неподходящий ответ, бот делает ещё одну генерацию. После повторного отклонения на
прямое обращение используется резервная реплика; в автоматическом режиме бот молчит.
Пунктуация и регистр не обходят эту проверку. Тематическую уместность проверяйте в живом чате.

## Обслуживание

```bash
sudo systemctl status volodymyr-bot --no-pager
sudo journalctl -u volodymyr-bot -n 60 --no-pager
sudo systemctl restart volodymyr-bot
sudo systemctl stop volodymyr-bot
df -h /
ollama ps
```

Журнал не пишет токен, содержимое чата, запросы к модели и полные ответы модели.
Для отклонённой реплики он пишет только фиксированную причину и номер попытки:
`empty_response`, `response_too_long`, `reasoning_in_response`, `multiline_response`,
`restricted_terms`, `sensitive_data`, `length_limit`, `repeated_response`,
`silence_on_direct_request`, `model_error`, `malformed_response`, `unrelated_topic`
или `stale_catchphrase`. Недоступность
Ollama отмечается как `model_unavailable`; ошибка локального поиска — как
`local_generation_error`. Выбор резервной фразы пишет только сообщение
«Использована резервная реплика, режим=manual». Для диагностики используйте
`sudo journalctl -u volodymyr-bot -n 60 --no-pager`.
Для прямых обращений журнал отдельно отмечает получение сообщения, постановку
в очередь, начало обработки и отправку. Причины пропуска: `request_cooldown`
(обращения чаще раза в 15 секунд), `queue_full`, `send_cooldown` (15 секунд ещё
не прошло после предыдущей отправки), `job_expired` (задание старше 3 минут),
`chat_changed` и `telegram_retry_after` (пауза, которую потребовал Telegram).
Если новое обращение не отображается ни в `/status`, ни в журнале, проверяйте
доставку обновлений Telegram, настройки приватности и правильность подключённой группы.
Выбор молчания в автоматическом режиме не считается ошибкой и не перегенерируется.
Основной расход диска — установленная модель.
Для резервной копии остановите службу и скопируйте каталог проекта целиком, включая `state`.
Резервная копия содержит секретный токен.

## Проверки пакета

Локальные проверки без Telegram: `python3 -m unittest discover -s tests -v`.
Они проверяют ограничение групп и владельца, повторные обновления, сохранение лимитов,
тихие часы, отмену автоматического ответа во время генерации, обработку неопределённой
отправки и реальный поиск по корпусу. Работу с вашим токеном и запущенной Ollama нужно
проверить после установки на VM.
